# HelloChat engineering notes

- Core ML can time out during recognition or during the subsequent model reload. Keep the NSError domain through the listener, retry both paths with one bounded recovery budget, and replenish it only after processed audio. Preserve native Voice and the listening preference during local recovery. After exhaustion, power/display changes or system wake can retry; automatic undock/redock still owns its two-minute delay. Await the old worker's cleanup before loading another; task cancellation cannot forcibly interrupt a Core ML call already in progress.
- Phrase timing belongs to the audio timeline, not the arrival time of an entire transcript. Nemotron exposes live token timings; Parakeet exposes raw token pieces and millisecond timestamps; Apple time-indexed progressive results expose audio ranges. Normalize these into matching word spans. If alignment is unavailable, retain first-observed times across prefix/suffix revisions. Apply proximity to both wake and end matching, including standalone stops during Agent Flow dictation, without delaying valid detections. Text-only dictionary highlighting remains a textual match, not proof that timing allowed a command.

- Agent Flow's recording guard used to block both wake and end phrases. Keep wakes and phrase mentions suppressed during dictation, but allow standalone end phrases (including repetitions) through the same local recognizer. Match the whole utterance with the existing dictionary so discussing an end phrase does not itself stop Voice.
- Use the configured Codex `realtimeVoice.endCall` for explicit ends. The old unassigned-End toggle fallback was removed; never use Start/Toggle to end a call. Agent Flow's shared F20 command only coordinates microphone mute, not call ending. Sending a complete process-targeted key event is different from physically pressing the component modifiers in sequence.

- Compact dictionary matching can erase meaningful word boundaries: ordinary "high at" becomes `highat`, which is generated by `hi` plus `ghat` (a one-letter edit of Chat). Exclude the compact ordinary phrase in the shared matcher, as with `highhat` and `hellchat`, so detection and highlighting agree. Keep Hi Chat, Hello Chat, explicit custom phrases and later genuine wakes covered separately. A reproduced saved-text match identifies a plausible cause, not the exact unsaved intermediate recognition at an earlier event.

- A moving input meter does not prove recognition. Keep recorded-fixture checks separate from physical microphone/Voice acceptance.
- Core ML cpuAndNeuralEngine allows CPU work. Compute-plan estimates do not measure real hardware utilization. Bundle pinned assets and disable model downloads while listening.
- Codex Voice must be established through exact live controls. A microphone process alone can be dictation or a residual stream; an incomplete negative accessibility scan proves nothing.
- Never cache an End control or use a start-capable toggle for cleanup. A stale toggle can reopen a call.
- Keep microphone capture input-only and pinned to the selected device; avoid changing system audio routing.
- Return promptly from AppKit termination callbacks, then clean up asynchronously; blocking the main actor can starve recognition and cleanup.
- Recognition buffers, diagnostics, and transcript contexts are bounded. Tests cannot prove indefinite leak freedom or absence of false wakes.
- Publication rename: HelloChat replaces Hey Chat. Preserve the signing identifier and process lock so privacy grants and single-instance ownership survive the rename. Migrate data without overwriting collisions. Resolve Codex by bundle identity and actual executable, not one developer's installation path.
- Recorded checks should regenerate when the fixture generator changes. A continuous synthesized Hello Chat / Bye Chat recording exercises both commands; a short isolated synthesized Bye Chat was missed. Fixture success must not be presented as proof of quiet-room, isolated-phrase, accent, or real-microphone accuracy.
- The legacy daily-backup format identifier and remote destination remain stable during branding migrations so existing receipts and remote history are preserved.
- Use a fixed local calendar time for the daily transcript backup; an elapsed 24-hour interval drifts with job loading and RunAtLoad also starts uploads during login. Ethan requested overnight backups on 2026-10-31, so the installer uses 05:45 and no login trigger. Preserve the existing dedicated Drive route when installing; calendar jobs missed during sleep run after wake, rather than waking the Mac themselves.
- Generate icons and sharing images in explicit pixel-backed bitmap contexts. NSImage.lockFocus inherits display scale and can silently double the advertised image dimensions.
- Test background transcript persistence by waiting for the file with a bounded deadline, without calling flush. A fixed sleep barely longer than the throttle can fail when the utility queue is delayed by other work.
- A failed application-identity snapshot during Voice startup does not prove Codex quit. Correlate process start time and Codex's own window/call logs; a live call can coexist with HelloChat reporting "Codex closed while opening Voice."
- Startup-error cleanup can request End while a native call is successfully opening, and an End request can time out while the call remains responsive. Preserve the failed snapshot and cleanup sequence before reproducing; do not infer call termination from a dispatched request.
- Retry missing application identity within the existing startup deadline without resending Start. Ordinary confirmation errors relinquish pending ownership without sending End; explicit cancellation still uses owned late-call cleanup. Injected-transport checks cover missing initial identity, missing identity after Start, bounded timeout and later adoption, changed process identity, and cancellation during an in-flight Start.
- Large Codex accessibility trees can exhaust the 12,000-node Voice-control scan before it proves Voice is absent. Three capped scans can produce "Couldn't confirm Codex Voice" before any Start shortcut is sent. Treat this as an incomplete control read, not failed phrase recognition or proof that a floating window covered a control.
- Persist the explicit listening choice separately from live capture state. Normal mode restores both On and Off across app restarts without requiring an external display; playback pauses, failures and shutdown must not overwrite that choice. Keep the existing automaticListening key opt-in and preserve its saved docking behavior independently.
- Docking is an automatic trigger, not a prerequisite for manual listening. A saved manual On must bypass both the dock policy and the start guard; dock events must not stop it. An automatic start must not save a manual override, so unplugging still stops capture that was started only by docking.
- Heard transcript highlighting needs both saved phrases and the matcher's ending flag for closing aliases. Keep the end phrase in the view's equality state so editing it refreshes colours; resolve overlapping custom matches without duplicating or changing recognized text.

- Parakeet EOU is an explicit one-shot SDK signal. Arm its debounce only after the first recognized words: silent priming can otherwise latch completion before speech, causing repeated resets in the 160 ms backend. It is re-armed by resetting the recognition context when speech resumes. Feed the latest transcript before marking its revision complete; a later correction invalidates that completion. Nemotron has no EOU output in the pinned local backend, so quiet audio plus stable text is a fallback, not native EOU. Keep end commands immediate and cancel pending wakes. Exercise repeated utterances through the recorded production listener; text-only matcher checks cannot prove endpoint timing. Since 1 Nov the wake no longer waits for EOU or silence, so EOU only feeds diagnostics.
- Window placement is an app preference, separate from agent testing display rules. Persist the selected display UUID locally, preserve it while disconnected, and fall back to an available display without shipping personal monitor identifiers.

- Chromium AX web areas support native AXButtonSearchKey queries. Search those buttons rather than walking thousands of transcript nodes; an exact current microphone control can identify a Voice presentation whose End control is absent. Preserve fresh-tree validation and never retry the start/stop toggle blindly.
- Agent Flow command suppression follows its Core Audio input activity rather than its media playback notifications or TTS admission grants. Clear pending audio/recognition context at recording boundaries so late pre-boundary words cannot wake or end a call afterward.
- Fit transcript height against the outer Form viewport only when a readable area remains. Keep its own scroll position independent of the form and stop following when the reader scrolls back; timestamp removal is UI-only, not removal of archive timing.
- New Voice speed belongs to Codex's native launch: the current global shortcut carries no per-call service tier and inherits Codex's saved speed. An unsupported Ultra Fast tier does not imply an automatic Fast fallback. Query the selected model's advertised tiers and apply an explicit tier to the actual new thread before claiming this works; blindly sending a slash-command toggle can instead turn an already enabled tier off. Preserve existing calls and unrelated chat settings.

- The wake sound acknowledges detection, not creation of a new Codex call. Dispatch it synchronously at the detection boundary, including when a previous Voice action is busy; a busy detection must never schedule another call. Manual Start also acknowledges before scheduling Voice work. Keep connection status separate from this cue, and preserve the completed-utterance/mention filters. Rewind reused sounds and log request/play timing, disabled settings and missing resources so silence can be diagnosed. This supersedes the former policy that made busy detections silent.
- An explicit wake retries transient native-control reads, then makes one start attempt if Codex is present and Accessibility is allowed even when controls remain unknown. This is the requested fail-open policy for starting only: an exact existing Voice control still reuses/unmutes that call; no blind toggle retries, End, or cleanup are authorized by uncertainty. Agent Flow recording and phrase-context suppression remain separate gates.

- Swift 6.3 can fail to diagnose a generic async operation whose body only calls fatalError when it is used from Task<Void, Error>. Give that test closure an explicit async throws -> Void result. The Mini test suite then compiles and still verifies that cancellation prevents the operation from running.

- Background sound can keep Nemotron/Apple above the fixed quiet threshold even when the transcript has stopped changing. A trailing direct address stable for 1.2 seconds may complete without silence; preserve mention filters, consumed occurrences, End cancellation and Parakeet native EOU. This intentionally changes the old wait-for-silence timing, and may accept a direct phrase before later words arrive. Log numerical quiet/stable duration and decision only, never recognized words in diagnostics.

- Superseded on 1 Nov 2026 at Ethan's request: a wake fires as soon as the phrase is heard, with no pause or stable-text wait. With constant room noise (`quiet_s` stayed 0 all day), a wake followed by more words never completed, so a second "Hello Chat" at 12:15:29 logged only `waiting_for_completion` and made no sound. Words heard before the phrase still filter mentions; words after it cannot cancel a wake. Separately, phrases are ignored while Agent Flow records, so a test "Hello Chat" said mid-dictation is silent by design.
- The default dictionary only accepts Chat spellings that start with "ch". The sh/cat/hat/that names and unrestricted one-edit names were too lenient: "UI shit" highlighted as Bye Chat, and "by what" matched through the one-edit name "what". Hey/Hay addresses are excluded because Ethan says "Hey Chat" when discussing the app. Keep explicit ordinary-phrase exclusions as a safety net.
- Refresh (2 Nov 2026, Ethan's request) re-reads Codex once on demand so a call opened or closed in Codex no longer leaves HelloChat showing the wrong state. A read that finds no Voice controls counts as off, even when incomplete, matching the fail-open start rule. Don't add background polling for this.
- On 2 Nov 2026 build 58's `realtimeVoice.endCall` shortcut (Ctrl+Option+Shift+V, process-targeted) never ended a call: Codex's log showed one call from 19:25 to 20:18 through five Bye Chat attempts, and the End-button fallback didn't end it either. HelloChat's "still on" reading was correct. Codex registers End as an app-scoped command next to the start toggle, which does work. The cause is still unproven, so test a real key press before changing the End path again.

- Hardened-runtime Developer ID builds require `com.apple.security.device.audio-input` in the signed entitlements; `NSMicrophoneUsageDescription` alone does not permit capture. Keep the original bundle identifier and team to preserve existing privacy identity. Public packaging must verify the actual signed entitlement and notarise/staple the final app before advertising a notarised download.

- New Macs need the global `realtimeVoice` Start shortcut and dedicated app `realtimeVoice.endCall`. Fill only absent, blank or null keys, preserve custom bindings, compare modifier aliases when checking collisions, and reject malformed settings without rewriting them. `composer.startVoiceMode` is the unrelated Toggle setting and must stay untouched. Re-read settings at delivery; writing a binding alone does not prove Codex handled it.
- Layout analysis found that Dvorak - QWERTY Command translates physical key 9 to K without Command and V with Command; plain V is key 47. This did not prove that Codex failed to accept its registered shortcut. Ethan asked to remove the unverified layout-delivery change and first use the dedicated configured Start/End bindings. Keep that delivery unchanged unless a later observed result and current authorization justify a change.
- Normal H Chat Quit must detach local control before cancelling pending Voice work. Cancellation recovery otherwise calls End and can hang up a running or late-opened Codex conversation. Keep explicit End/off cleanup separate, and preserve the wake acknowledgement plus fresh-active-call reuse guard.

- The installed Codex UI labels `realtimeVoice` as Voice chat hotkey and `composer.startVoiceMode` as Toggle voice chat. H Chat must configure/send only the former for Start, with the current approved Command-Control-Shift-V default, and leave Toggle alone. End remains `realtimeVoice.endCall`. The global Start needs macOS global event delivery; process-targeted dispatch remains for app-scoped End/microphone actions. A temporary T binding used to identify the UI setting is not the default.
- Codex's native keybinding update service applies registration side effects that external JSON writes skip. A restart made the saved End binding visible in the reported UI. Track H Chat's writes made while Codex is running and show the restart requirement; file parsing and successful event posting are not live acceptance evidence. Do not restart Codex or interrupt a call merely to clear that status.
- On a wake with Codex closed, prepare shortcuts before launching the bundle-identified installed app, then await finished launch plus an accessible web window. Recheck for a call after activation before one global Start. Tests inject launch/readiness and cancellation; they never launch real Voice.
- The user reported successful End while the helper still showed failure. The captured polls continued to report a microphone control and input activity until timeout. These reads do not establish that the call remained open: retain the working dedicated End action, distinguish an unconfirmed result from failure, and show unknown status when confirmation expires.

- Closing Codex's last window can leave its process running, so absence of a process is not the only launch condition. A wake must request the normal single-instance reopen when there is no usable app window. Keep the previous fail-open behavior for a running app with an incomplete control read; only a real launch or window-open transition needs readiness waiting.
- CGEvent timestamps are nanoseconds, but mach_absolute_time returns hardware ticks. The M1 probe reported a 125/3 timebase. Convert before assigning event timestamps; this fixes a verified unit error but does not by itself prove that a previous Voice failure was caused by it. The earlier successful and later failed End requests used the same dedicated End routine.

- The user changed Start's intended default to Command-Control-Shift-V, omitting Option. Local Agent Flow has a modifier-only Shift-Control-Option recording shortcut (917504), and manually trying the old all-modifier F8 chord triggered recording. This is a possible cross-app modifier conflict; the exact transition that caused it was not captured. - An isolated F18 event probe reproduced synthetic modifier state remaining after key-up repeated all modifier flags; restoring the original pre-send flags on key-up cleared that state. The probe did not establish successful Carbon hotkey activation, so it is not evidence of live Voice acceptance. - Codex saved the user's tilde choice as `Ctrl+Shift+` followed by a backtick, not as two ordinary keys. Preserve that exact setting; the backtick is physical grave (50), with Shift supplied by the saved modifier. Parse modifier aliases and case separately from the base key, support ordinary punctuation/navigation keys, and never direct users to a bare F17 when their chosen shortcut includes modifiers. This standard-key parser does not change the keyboard layout.

- Chromium's native global accelerator registration maps a base character through the current layout with no modifiers, then registers the full accelerator modifier set. The installed framework contains LayoutAwareGlobalHotkeys. Mirror that separation: do not use a Command-only layout probe or NSEvent control characters to guess the physical key. A fixed QWERTY semicolon was S on the tested Dvorak layout; the user's Ctrl-Shift-colon mapped to key 6. Keep function/navigation keys fixed and read the active character layout at each delivery without changing OS settings. Source: Chromium ui/base/accelerators/global_accelerator_listener/global_accelerator_listener_mac.mm, RegisterHotKey.
- An old Codex process can exit after its reopen request but before window readiness. Track that identity transition and permit one fresh application launch while retaining a single eventual Voice key request. Do not poll a vanished PID until timeout or blindly resend Voice.

- The user confirmed build 70 could start and end a real call with both a punctuation Start binding and the Command-Control-Shift-V binding. Keep active-layout base-key resolution separate from the full saved modifier flags. This live evidence belongs to those tested bindings; it is not proof of every keyboard layout.
- A visible Electron web area can appear before the native Voice shortcut is ready. The user reported early Start after automatic launch and authorized a short launch-only wait. The implementation requires interactive readiness, keeps a five-second minimum for opening/reopening, and bounds each launch attempt at ten seconds. A seven-second web-shell fallback was rejected because it sent before the delayed-ready fixture reached nine seconds. Do not add this wait to an already-ready app or resend Start.
- The optional transcript-backup job is installed separately on each Mac. A blanket Settings claim that Google Drive backup runs daily was false on an installation without that LaunchAgent. Inspect local configuration before describing it; do not enable uploads to repair the text.

- Every pending native Start has a request identity. Environmental capture pauses preserve the call and clear only that request’s pending ownership; positive call reuse also clears completed opening state. Otherwise the first explicit End can incorrectly bypass the fresh microphone-only End path. An old cancelled request must not clear a newer opening’s state.
- Sparkle invokes its postpone callback once. A downloaded update needs pending-only rechecks and coalescing of events received during an async snapshot; stop the checks on abort or installation. Preparation must be reversible if installer IPC fails before app termination. Reattach native control and re-evaluate current listening preferences and device state without changing saved values.
- Launch Services relaunch is outside a custom launchd job. Before taking the instance lock or starting any capture, an updated app can hand off to a matching, already-loaded owned job. Never bootstrap an absent job, change custom arguments, force a nonzero exit, or use kickstart -k. The isolated signed-update fixture verified installation, automatic relaunch under its test job and restart after a deliberate abnormal exit.
- Rebuilding a bundle in place must replace the SwiftPM resource bundle as a unit: its packaged files can be read-only, causing the second ordinary copy to fail. Clear only that owned build output, preserving installed apps and source assets.
- An update's preparation awaits cancelled Voice work, so recheck recording/call safety afterward. If safety changed, restore the runtime and keep the downloaded offer pending. On abort, preserve an existing dock deadline and immediately resume a previously active listener only while current preferences and environment still permit it; genuine setting, playback or dock changes invalidate that saved delay.
- A wake sound during a pending Start is only another acknowledgement: the 4 Nov 18:51:45 wake arrived ten seconds into an unconfirmed request and emitted no new shortcut. A locked/inactive desktop must fail Start promptly, with session state logged, rather than hold that request until confirmation timeout. Lock, unlock and session switches clear old recognition context and cancel only that opening with call-preserving ownership; unlocking never automatically starts a call. Preserve the active-layout key mapping and dedicated End path.

- A successful Carbon `RegisterEventHotKey` probe does not establish that a shortcut is unregistered. An exclusive registration also temporarily suppresses ordinary owners; do not use it during a real shortcut test or infer Codex's registered physical key from success. The harmless character-key receiver must actually receive its callback before its sender is considered tested; F18 alone did not establish that.
- A diagnostic launched from Codex can inherit Codex as its responsible app for macOS privacy checks. It exits before the instance lock, listener, or Voice commands; remove only that temporary job after reading the result. Configured prose/commands values feed the editor chooser, but account policy can force the effective value or leave it unresolved. The renderer also has route/presentation and role fallbacks. A manual Start failure followed by a restart, a mode change, and a successful call does not isolate which change restored Voice. A successful source push or local installation is not completion of the release/update system.
